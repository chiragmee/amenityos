**2026-09-12** — Fixed a second, different cause of slow transcription after the user reported it was "still" slow post-Gemini-swap. Root cause this time: a real transient 503 from `gemini-flash-lite-latest`, compounded by the `google-genai` SDK's default retry policy (5 attempts, exponential backoff up to 60s) — confirmed in production logs, a single transcription call hung ~57s entirely inside the SDK's own internal retry loop before ever reaching this app's code. Worse, this client is shared with the chat orchestrator, which has its own outer retry loop (`_send_with_retry`) — every chat turn was paying for two compounding retry layers on any transient error. Fixed at the shared client level (`gemini_client.py`): capped the SDK's own retries to 1 fast attempt via `http_options`, 20s per-call timeout — real retry/backoff decisions now happen only in this app's own visible code. Also gave voice transcription its own explicit 1-retry wrapper (it previously had zero resilience, unlike chat). Verified: normal latency unaffected (~0.7-1.3s), 25/25 tests pass.
Why: real user-reported latency problem, found by reading production logs rather than re-guessing at CPU/model causes.
Files: `backend/app/gemini_client.py`, `backend/app/voice/recognizer.py`

**2026-09-12** — Built Phase D (observability + eval), the last phase of the 4-phase AI roadmap, and used it to find and fix 3 real bugs rather than just producing a report. New `AgentTrace` table + orchestrator instrumentation capture per-turn tool calls, tokens, retrieval, and latency (docs/12); new admin API + `/admin/traces` page to inspect them. The eval process itself surfaced: (1) a real security gap — `get_booking`/`generate_access_token` had no ownership check, and identity-sensitive tools accepted an LLM-supplied `user_id` instead of the trusted caller's, letting any user read another's booking/access-token/credit data — fixed by binding identity to the authenticated request everywhere it matters and adding explicit ownership checks; (2) Gemini 429 rate-limit responses crashed into an unhandled 500 instead of degrading gracefully — fixed; (3) ambiguous requests were sometimes answered by guessing instead of asking, non-deterministically — fixed with an explicit AMBIGUITY section added to the system prompt (docs/03 + system_prompt.py, PROMPT_VERSION bumped), re-verified empirically (1/4 → 4/4 ambiguity cases passing). Final suite result: 29/29 passing. Also discovered mid-run that the free-tier Gemini key has a hard daily quota (500 req/day) — burned through it partway via repeated eval reruns; the retry/degrade fix meant this didn't corrupt results, just added latency.
Why: closes the AI roadmap (A: agent, B: RAG, C: voice, D: this) — the point of an eval suite is to surface real gaps, and this one did.
